# OpenClaw 2026.3.28 Tool Schema Changes Research

**Date:** 2026-03-31  
**Researcher:** Karen (Subagent)  
**Status:** Complete

---

## Executive Summary

The "Missing required parameter: path alias" error is a known regression in OpenClaw 2026.3.28 (and earlier versions 2026.3.24+) affecting Kimi models. The issue stems from tool parameter aliasing changes where the Kimi model fails to consistently pass required parameters, particularly when parameter aliases exist.

---

## 1. The Core Issue

### Error Pattern
```
[tools] read failed: Missing required parameter: path alias. Supply correct parameters before retrying.
[tools] write failed: Validation failed for tool "write": content: must have required property 'content'
[tools] exec failed: Validation failed for tool "exec": command: must have required property 'command'
```

### Root Cause
The Kimi model (kimi-coding/k2p5) has inconsistent handling of `required` fields in tool schemas. When tools have parameter aliases (e.g., `file_path` and `path` for the read tool), the model may:
- Call tools with empty `{}` arguments
- Omit required parameters entirely
- Fail to recognize parameter aliases

### Affected Tools
| Tool | Primary Parameter | Alias | Error Message |
|------|------------------|-------|---------------|
| `read` | `file_path` | `path` | "Missing required parameter: path alias" |
| `write` | `file_path` | `path` | "content: must have required property 'content'" |
| `edit` | `file_path` | `path` | "Missing required parameters: path alias, oldText alias, newText alias" |
| `exec` | `command` | - | "command: must have required property 'command'" |
| `process` | `action` | - | "action: must have required property 'action'" |
| `sessions_spawn` | `task` | - | "task: must have required property 'task'" |

## 3. What Changed in 3.28

### Tool Schema Validation Changes

Based on release notes and issue analysis:

1. **Stricter Validation:** OpenClaw 2026.3.28 introduced stricter tool parameter validation
2. **Parameter Aliasing:** The `read` and `write` tools support both `file_path` and `path` as aliases
3. **Kimi Model Behavior:** Kimi k2p5 model doesn't consistently respect JSON Schema `required` fields
4. **Empty Object Fallback:** When parameter construction fails, LLM falls back to passing `{}`

### PR #7451 - Historical Fix

The fix for similar issues in earlier versions:
- **Title:** "ensure file_path alias passes validation in read/write tools"
- **Solution:** Ensure parameter aliases are properly handled during validation
- **Files:** Modified read/write tool validation logic

## 4. How to Fix "Path Alias" Errors

### Immediate Workarounds

1. **Add to SOUL.md:** Include mandatory self-check lists for tool calls
2. **Explicit Parameters:** Always use explicit parameter names in tool calls
3. **Model Switch:** Temporarily use non-Kimi models if available

### Configuration Changes

No specific config changes required - this is a model/gateway interaction issue.

### Code-Level Fix (For OpenClaw Developers)

Based on issue #55039, the fix involves:

```typescript
// In tool definition, enhance description:
{
  name: "read",
  description: "Read a file. The path parameter is REQUIRED. Example: path='BOOTSTRAP.md'",
  parameters: {
    // ... schema
  }
}
```

## 5. Migration from 3.2 to 3.28

### No Breaking Config Changes
- Config format remains compatible
- No required config updates

### Behavioral Changes
- Tool validation is stricter
- Kimi models may require more explicit parameter guidance
- Empty tool calls are rejected more aggressively

### Recommended Actions
1. Monitor tool call success rates after upgrade
2. Add explicit parameter documentation to agent SOUL.md files
3. Consider adding pre-validation logic for critical tool calls

## 7. Key Takeaways

1. **Not a Configuration Issue:** This is a model behavior + validation interaction issue
2. **Kimi-Specific:** Primarily affects Kimi k2p5/kimi-coding models
3. **Regression:** Worked correctly before 2026.3.24/3.28
4. **Workaround Available:** Explicit parameter guidance in tool descriptions helps
5. **Fix in Progress:** OpenClaw team is aware and working on fixes
