For a 20GB RAM Windows 11 system with ~12GB available RAM and no GPU, the optimal setup is:

1. **Primary Tool:** Ollama (ease of use, good CPU support)
2. **Alternative:** llama.cpp (more control, slightly faster)

4. **Best Models:** Qwen 2.5 7B, Llama 3.2 3B/7B, Phi-4, Gemma 3

**Expected Performance:** 5-15 tokens/second depending on model and quantization

## 2. BitNet 1.58: The Game Changer

### What is BitNet 1.58?

BitNet b1.58 is Microsoft's 1-bit LLM technology using ternary weights (-1, 0, +1):
- **Memory reduction:** ~10x smaller than FP16
- **Speed increase:** 2.37x - 6.17x faster on x86 CPUs
- **Energy reduction:** 71.9% - 82.2% less power

### BitNet Models Available

| Model | Effective Size | RAM Needed | Tokens/sec (x86) | Status |
|-------|---------------|------------|------------------|--------|
| **BitNet-b1.58-2B-4T** | ~500MB | ~1GB | 20-30 tok/s | ✅ Available |
| **Falcon3-1B-1.58bit** | ~250MB | ~500MB | 30+ tok/s | ✅ Available |
| **Falcon3-3B-1.58bit** | ~750MB | ~1.5GB | 20-25 tok/s | ✅ Available |
| **Falcon3-7B-1.58bit** | ~1.75GB | ~3GB | 15-20 tok/s | ✅ Available |
| **Llama3-8B-1.58** | ~2GB | ~4GB | 12-18 tok/s | ✅ Available |

### BitNet Windows 11 Setup

```powershell
# Prerequisites: Visual Studio 2022 with C++ and Clang components

# 1. Clone repository
git clone --recursive https://github.com/microsoft/BitNet.git
cd BitNet

# 2. Create conda environment (recommended)
conda create -n bitnet-cpp python=3.9
conda activate bitnet-cpp

# 3. Install dependencies
pip install -r requirements.txt

# 4. Download model
huggingface-cli download microsoft/BitNet-b1.58-2B-4T-gguf --local-dir models/BitNet-b1.58-2B-4T

# 5. Build (run in VS2022 Developer Command Prompt)
python setup_env.py -md models/BitNet-b1.58-2B-4T -q i2_s

# 6. Run inference
python run_inference.py -m models/BitNet-b1.58-2B-4T/ggml-model-i2_s.gguf -p "You are a helpful assistant" -cnv -t 8
```

### BitNet Limitations (April 2026)

- ❌ Limited model selection (mostly Microsoft/Falcon)
- ❌ Requires build from source on Windows
- ❌ No Ollama integration yet
- ❌ Newer architecture, less community support
- ✅ Worth watching - could revolutionize local LLMs

## 3. Ollama vs llama.cpp vs Lemonade SDK

### Head-to-Head Comparison

| Feature | Ollama | llama.cpp | Lemonade SDK |
|---------|--------|-----------|--------------|
| **Setup Difficulty** | Easy ⭐ | Medium | Medium-Hard |
| **Windows Support** | Native ⭐ | Native | Native |
| **CPU Performance** | Good | Better ⭐ | Good |
| **Model Management** | Automatic ⭐ | Manual | Manual |
| **Memory Efficiency** | Good | Good | Good |
| **Tool Calling** | Via external | Native (llama-server) | Limited |
| **Quantization Control** | Limited | Full ⭐ | Limited |
| **API** | REST built-in | HTTP optional | Custom |
| **Best For** | Daily use | Power users | GPU/NPU focus |

### Recommendation for 20GB RAM System

**Use Ollama as primary** for these reasons:

1. **Convenience wins on limited RAM** - Automatic model management prevents mistakes
2. **CPU performance gap is small** - llama.cpp is ~5-10% faster, not worth complexity
3. **Dynamic context scaling** - Ollama auto-fits context to available RAM
4. **Better error handling** - Prevents loading models that exceed RAM

**Use llama.cpp directly when:**
- You need specific quantization not in Ollama
- You want maximum control over CPU threads
- You need MCP tool calling (March 2026 feature)
- You're comfortable with command line

### Performance Benchmarks (CPU Only, 8-core Ryzen)

| Tool | Model | Tokens/sec | Notes |
|------|-------|------------|-------|
| Ollama | Qwen 2.5 7B Q4 | ~8 tok/s | Easy setup |
| llama.cpp | Qwen 2.5 7B Q4 | ~9 tok/s | 10% faster |
| Ollama | Llama 3.2 3B Q4 | ~15 tok/s | Fastest practical |
| llama.cpp | Llama 3.2 3B Q4 | ~17 tok/s | Marginal gain |

## 4. Step-by-Step Windows 11 Setup

### Option A: Ollama Setup (RECOMMENDED)

```powershell
# 1. Install Ollama (run in PowerShell as Administrator)
winget install Ollama.Ollama

# 2. Or download from https://ollama.com/download/windows

# 3. Verify installation
ollama --version

# 4. Pull recommended models
ollama pull qwen2.5:7b           # Best balance
ollama pull llama3.2:3b          # Fastest
ollama pull phi4:4b              # Quality small

# 5. Test run
ollama run qwen2.5:7b

# 6. For API access (OpenWebUI, etc.)
ollama serve  # Runs on localhost:11434
```

### Ollama Configuration for 12GB RAM

```powershell
# Set environment variables (System Properties > Advanced > Environment Variables)
# Or via PowerShell:
[Environment]::SetEnvironmentVariable("OLLAMA_NUM_PARALLEL", "1", "User")
[Environment]::SetEnvironmentVariable("OLLAMA_MAX_LOADED_MODELS", "1", "User")
[Environment]::SetEnvironmentVariable("OLLAMA_KEEP_ALIVE", "5m", "User")

# Restart Ollama after setting variables
```

### Option B: llama.cpp Setup (Advanced)

```powershell
# 1. Install prerequisites
winget install Git.Git
winget install Kitware.CMake
# Install Visual Studio 2022 Community with C++ workload

# 2. Clone and build
git clone https://github.com/ggerganov/llama.cpp.git
cd llama.cpp

# 3. Build for CPU only
cmake -B build -DLLAMA_CUDA=OFF -DLLAMA_OPENBLAS=ON
cmake --build build --config Release

# 4. Download models manually from HuggingFace (GGUF format)
# Recommended: https://huggingface.co/bartowski/Qwen2.5-7B-Instruct-GGUF

# 5. Run inference
.\build\bin\Release\llama-cli.exe -m qwen2.5-7b-q4_k_m.gguf -p "Hello" -n 256 -t 8
```

### Factors Affecting Performance

1. **CPU cores/threads** - More is better (use `-t` flag to set)
2. **RAM speed** - DDR4 vs DDR5 matters for CPU inference
3. **Context length** - Longer = slower (keep to 4K-8K for speed)
4. **Prompt size** - Large prompts process slower
5. **Windows background processes** - Close unnecessary apps

## 6. Known Issues on 20GB Systems

### Critical Issues

#### 1. Memory Allocation Failures
**Symptom:** "memory layout cannot be allocated" or "host alloc failure"
**Cause:** Windows + background apps consume 8GB, leaving insufficient RAM
**Fix:** 
- Close all unnecessary applications
- Set OLLAMA_MAX_LOADED_MODELS=1
- Use smaller models (7B instead of 14B)
- Restart Ollama service: `taskkill /F /IM ollama.exe`

#### 2. Windows Page File Thrashing
**Symptom:** System becomes unresponsive during inference
**Cause:** Windows swaps to disk when RAM exhausted
**Fix:**
- Increase page file to 16GB minimum
- System Properties > Advanced > Performance Settings > Advanced > Virtual Memory
- Set custom size: Initial 16384 MB, Maximum 32768 MB

#### 3. Model Loading Failures >10GB
**Symptom:** Models fail to load despite "enough" RAM
**Cause:** Windows memory fragmentation, GPU memory reservation
**Fix:**
- Use Q4_K_M quantization (not Q8_0)
- Restart before loading large models
- Disable GPU if present: `set CUDA_VISIBLE_DEVICES=""`

### Ollama-Specific Issues

| Issue | Solution |
|-------|----------|
| Slow first response | Normal - model loading into RAM |
| "Error: model not found" | Run `ollama pull <model>` first |
| High RAM after unload | Set `OLLAMA_KEEP_ALIVE=5m` or `0` |
| Concurrent request queue | Ollama serializes on CPU - use one request at a time |

### Windows 11 Specific

| Issue | Solution |
|-------|----------|
| Windows Defender scanning | Add Ollama folder to exclusions |
| Memory compression | Disable via `Disable-MMAgent -MemoryCompression` |
| SysMain service | Disable if RAM < 16GB total |
