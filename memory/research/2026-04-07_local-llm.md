## Key Insights

### 1. Ollama Autotune: Automatic Hardware-Based Performance Optimization

A major upcoming feature (PR #15081) introduces **autotune** - an automatic hardware detection and optimization system for Ollama. This eliminates the guesswork of configuring environment variables.

**Key Features:**
- Detects GPU VRAM, CPU cores, and RAM automatically
- Provides 5 performance profiles: `balanced`, `speed`, `memory`, `multiuser`, and `max`
- New CLI commands: `ollama autotune status`, `ollama autotune profiles`, `ollama autotune apply`
- API endpoints for programmatic profile management

**Profile Use Cases:**
| Profile | Best For | Key Settings |
|---------|----------|--------------|
| `balanced` | Default, general use | Auto-scaled to hardware |
| `speed` | Single-user, max throughput | KEEP_ALIVE=30m, optimized threading |
| `memory` | Low-VRAM GPUs (<6GB) | Reduced context, conservative memory |
| `multiuser` | Shared servers | NUM_PARALLEL=4, shorter keep-alive |
| `max` | High-end GPUs | Max context, aggressive settings |

### 2. The Three-Stack Landscape: Clear Separation of Use Cases

In 2026, three tools dominate with distinct purposes:

| Tool | Best For | Throughput | Setup |
|------|----------|------------|-------|
| **Ollama** | Desktop/local AI, prototyping | ~35-41 tok/s (single user) | 1 minute |
| **llama.cpp** | Edge devices, CPU inference, max control | ~150 tok/s (single user) | 10-20 minutes |
| **vLLM** | Production serving, multi-user | 5,841+ tok/s (batched) | 1-2 hours |

**Key Takeaway:** Ollama adds ~10-15% overhead vs raw llama.cpp but provides unmatched convenience. vLLM's PagedAttention enables 4x more concurrent sequences than standard implementations.

## Optimization Recommendations

### For Ollama Users:
1. Enable `OLLAMA_FLASH_ATTENTION=1` for better context window performance
2. Use Vulkan (`OLLAMA_VULKAN=1`) on AMD systems instead of ROCm
3. Set `OLLAMA_METAL=1` on Apple Silicon for 2.8x faster inference
4. Watch for autotune feature release to eliminate manual tuning

### For llama.cpp Users:
1. Consider `ik_llama.cpp` fork for 3-5x faster CPU inference
2. Use Q4_K_M quantization as the default (best size/quality tradeoff)
3. Enable speculative decoding with small draft models (e.g., Qwen 3.5 0.8B for 27B)

### For Production Deployments:
1. Use vLLM for multi-user scenarios (14-24x higher throughput)
2. Implement hybrid stack: Ollama for dev, vLLM for production
3. Consider SGLang alongside vLLM for Qwen 3.5 (recommended by Qwen team)
