## Breaking Change #1: Node Exec Canonical Paths

### Problem
Node `system.run` execution now pins path-token commands to their canonical executable paths using `realpath`. Commands using simple tokens like `python` or `pwsh` will fail.

### Current State (BROKEN)
Cron jobs and exec calls using simple tokens:
```json
// jobs.json - BROKEN
{
  "text": "python C:\\Users\\Karen\\script.py"
}

// exec tool - BROKEN
{
  "command": "python script.py",
  "host": "node"
}
```

### Fix: Use Canonical Paths
Replace all simple tokens with full canonical paths:

| Token | Canonical Path |
|-------|---------------|
| `python` | `C:\Program Files\Python311\python.exe` |
| `python3` | `C:\Program Files\Python311\python.exe` |
| `pwsh` | `C:\Program Files\PowerShell\7\pwsh.exe` |
| `powershell` | `C:\WINDOWS\System32\WindowsPowerShell\v1.0\powershell.exe` |
| `node` | `C:\Program Files\nodejs\node.exe` |
| `npm` | `C:\Program Files\nodejs\npm.cmd` |

## Breaking Change #2: systemRunPlan Approval Requirements

### Problem
Node exec approval payloads now require a `systemRunPlan` field. Approval requests without this plan are rejected.

### What is systemRunPlan?
Based on the changelog, `systemRunPlan` appears to be a structured plan describing:
- Command intent
- Expected resources
- Safety constraints
- Execution context

### Current Config (NEEDS UPDATE)
```json
// openclaw.json - CURRENT
{
  "tools": {
    "exec": {
      "host": "node",
      "security": "full"
    }
  }
}
```

### Fix Options

#### Option A: Add systemRunPlan to Agent Defaults (RECOMMENDED)
Add a `systemRunPlan` template to agent defaults:

```json
// openclaw.json - ADD to agents.defaults
{
  "agents": {
    "defaults": {
      "systemRunPlan": {
        "version": "2026.3.1",
        "executionContext": "user-node",
        "allowedHosts": ["DESKTOP-M8AO8LN"],
        "pathResolution": "canonical",
        "approvalRequired": true
      }
    }
  }
}
```

#### Option B: Switch to Sandbox Host (SIMPLER)
If node-specific features aren't needed, switch to sandbox execution:

```json
// openclaw.json - ALTERNATIVE
{
  "tools": {
    "exec": {
      "host": "sandbox",
      "security": "allowlist"
    }
  }
}
```

**Pros of Option B:**
- No canonical path requirements
- No systemRunPlan needed
- Simpler configuration

**Cons of Option B:**
- Cannot access node-specific capabilities
- Limited to sandbox environment
- May not work with all scripts

## Issue #3: Memory Search Still Broken

### Problem
Memory search provider is set to "local" but `modelPath` points to a directory instead of a model file:

```json
// openclaw.json - CURRENT (BROKEN)
{
  "agents": {
    "defaults": {
      "memorySearch": {
        "provider": "local",
        "local": {
          "modelPath": "C:\\Users\\Karen\\Models\\all-MiniLM-L6-v2"
        }
      }
    }
  }
}
```

### Fix Options

#### Option A: Download Model File (RECOMMENDED)
1. Download the model file (GGUF format) to a specific file path
2. Update config to point to the file:

```json
// openclaw.json - FIXED
{
  "agents": {
    "defaults": {
      "memorySearch": {
        "provider": "local",
        "local": {
          "modelPath": "C:\\Users\\Karen\\Models\\all-MiniLM-L6-v2\\model.gguf"
        }
      }
    }
  }
}
```

#### Option B: Switch to Ollama Embeddings
Use Ollama for embeddings instead of local file:

```json
// openclaw.json - ALTERNATIVE
{
  "agents": {
    "defaults": {
      "memorySearch": {
        "provider": "ollama",
        "ollama": {
          "baseUrl": "http://localhost:11434",
          "model": "nomic-embed-text"
        }
      }
    }
  }
}
```

**Note:** Requires `nomic-embed-text` or similar embedding model in Ollama:
```bash
ollama pull nomic-embed-text
```

#### Option C: Disable Memory Search
If not needed, disable to avoid errors:

```json
// openclaw.json - DISABLE
{
  "agents": {
    "defaults": {
      "memorySearch": {
        "provider": "none"
      }
    }
  }
}
```
