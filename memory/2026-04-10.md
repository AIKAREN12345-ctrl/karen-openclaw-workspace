
## Bug: Telegram Double-Message Replay
**Time:** 2026-04-10 09:00 and 10:31
**Trigger:** RESEARCH-OPENCLAW and RESEARCH-KDP cron jobs firing in idle sessions
**Symptom:** My previous outbound message to Ken was re-delivered automatically when the system event processed
**Likely cause:** OpenClaw Telegram channel plugin replaying the last sent message when waking an idle session for a systemEvent with `wakeMode: now`
**Workaround:** Process cron reminders silently where possible; avoid sending reminder relay text when session is idle
**Status:** Needs OpenClaw framework fix; workaround in place
