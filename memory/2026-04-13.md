## 19:34 - Gateway Restart & Orphan Recovery Investigation

**What happened:**
- Ken asked when the gateway went down and why before the 18:34 restart
- Investigated logs: gateway restarted at 18:34:14 via `SIGUSR1` (manual restart)
- Log file started at 09:03, so earlier logs were rotated — exact downtime before 9 AM unknown
- After restart, orphan recovery found ~20 subagent sessions and replayed queued completions
- Same sessions were recovered multiple times (loop bug), causing message flood

**Investigation result:**
- ✅ No orphaned sessions remain (`abortedLastRun: true` found nowhere in session storage)
- ✅ The flood was a one-time transient event
- ✅ System is stable now

**Root cause:**
- OpenClaw framework bug: orphan recovery retries failed resumes without marking sessions as "recovery attempted"
- When resume fails (gateway timeout), the same orphan is found again on next scan

**Workaround:**
- Avoid gateway restarts during active subagent runs
- Long-term fix requires OpenClaw framework update
